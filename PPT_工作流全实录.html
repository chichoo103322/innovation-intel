Agent 不是聊天工具，是你的工作流引擎

刚才看到的全流程，Agent 替代的不是"思考"，而是"执行一套固定操作"

"AI 不就是问一句答一句吗"

那是 Chatbot。Agent 能读写文件、跑脚本、打开网页验证信息——它是端到端的执行器，不是一个答题器。

"每次都要重新解释需求，好烦"

CLAUDE.md 写一次放项目里，Agent 每次打开自动读。换电脑、换人，行为完全一致。

"AI 不能动我电脑上的文件吧"

Agent 创建/修改文件、执行 Python、调用 Chrome 渲染 PDF——全都能干。

你不是「AI 的使用者」

你是「工作流的定义者」。你定规则，Agent 来跑。你写的是 SOP，它当你的执行者。

你要做的就三件事：

1. 写提示词 → Agent 的操作手册
2. 写 CLAUDE.md → 项目的规矩
3. 装 Skill → 给 Agent 配专业工具

03

第一步：写好提示词 — Agent 的「操作手册」

你不是在"聊天"，你是在"写标准操作流程"。三个模块：边界 + 标准 + 步骤

提示词的三个核心模块

# 边界：什么能做、什么不能做

⛔ 仅限 29 座万亿城市

⛔ 日报仅采集当日内容

# 标准：怎样算合格（必须可验证）

· 每条通过 6 层验证

· 每条出 3 版洞察（A/B/C）

· 每板块至少 1 条 .gov.cn

# 步骤：按什么顺序执行

Step 1 搜索 → 2 验证 → 3 构建 → 4 校验 → 5 输出

1. 边界比能力重要

告诉它什么不能做，比告诉它做什么更能防错。

2. 标准要可验证

"质量好"不可验证。"每条 120 字"可以。

3. 步骤可中断可检查

每步有明确输出物，出问题知道卡哪。

4. 错误案例是最好的素材

每发现一个错，加一条规则。

04

一个提示词的进化史：从 29 行到 200+ 行

提示词不是一次写好的，是用了 28 次、每次加一条规则，慢慢"长"出来的

V1 · 基础框架

四大维度 + site: 限定

"你是情报分析师，从这些网站找信息，分四类整理"。29 行。

V2 · 质量闸门

6 层验证 + 29 城白名单

发现洛阳（非万亿城市）被收录，硬编码白名单和信源评分体系。

V3 · 纠错机制

日期校验 + 机构名 + 禁用词

发现"科技委写成了科委"，加入硬约束和自检清单。

V4 · 搜索重构

业务实义词取代抽象标签

搜"概念验证中心""揭榜挂帅"等实义词，命中率从 30% 跳到 80%。

V5 · Agent 原生

双重 WebFetch + 触发词 + 零打扰

发现 URL 可能编造，加入 Step 2.5+4.5 双重验证。固化"出日报"触发词。

05

第二步：CLAUDE.md — 项目的规矩，写一次管一辈子

放项目根目录，Agent 每次打开自动加载。定义优先级、触发词、工作流

CLAUDE.md 核心结构

## Priority 0: 真实性（不可侵犯）

1. 每条 URL 必须 WebFetch 验证

2. 严禁捏造 URL

3. 无法验证 → 直接丢弃

## Priority 1: 零打扰（全自动）

⛔ 绝对禁止询问 Yes/No

## Agent 工作流

触发词: 出日报 / 出周报 / 出月报

Step 1-6: 搜→验→写→校→出→发

优先级不能让步

不能为了凑够 8 条（P3）去编 URL（违反 P0）。高优先级是硬底线。

触发词机制

"出日报""出周报"→ Agent 自动启动对应全套流程。三个字触发。

跨机器一致

CLAUDE.md 跟着 Git 走。任何人 clone 后打开 CC，行为完全一样。

提示词 = 操作手册
CLAUDE.md = 项目宪法

06

第三步：把大任务拆成 Agent 能执行的小步骤

"做一份日报"太模糊。拆成 6 步，每步有输入有输出，卡哪步一看就知道

1

读规则

加载提示词 + CLAUDE.md，知道搜什么、标准是什么

2

WebSearch 全网搜索

CC 自带工具调搜索引擎，4 维度 × 15-20 次，返回标题+摘要+URL

2.5

WebFetch 逐条验证

打开每个 URL：能访问？标题匹配？数据准确？不通过就丢

3

写 JSON

通过验证的写成结构化数据，含标题、日期、摘要、3 版洞察

4

自动校验

跑校验脚本 → 有错自己改 → 再验 → 直到零错误

5-6

出 PDF + 分发

Chrome 渲染 → 发到桌面 → Git 提交

1. 每步有输入有输出

Step 2 出搜索结果列表，Step 3 出 JSON。中间插 2.5 做质量把关。

2. 验证步骤不能省

少一步验证 = 埋一颗雷。没有 2.5，URL 可能全是编的。

3. 顺序就是质量防线

把验证插在容易出错的环节后面，错误在源头就被拦住。

07

第四步：Skill — 给 Agent「装插件」

Agent 自带通用能力。遇到专业需求，装个 Skill 就行了

文档处理

PDF Viewer

交互式查看、批注、文本提取。用于预览生成的日报 PDF。

演示文稿

Frontend Slides

零依赖 HTML 幻灯片。这份 PPT 就是 Agent 调用这个 Skill 生成的。

数据分析

BigQuery

Agent 直接写 SQL 查数据库、出分析报告。

Skill 的本质：把专业能力封装成 Agent 能调用的工具。任何重复性专业工作 → 封装为 Skill → Agent 即获该领域能力。

08

Codex vs Claude Code：怎么选 Agent

两个主流 Agent，定位完全不同。选对工具，事半功倍

OpenAI Codex

「大脑」— 推理与生成引擎

  • 顶级代码理解和生成，复杂推理强
  • 云端沙箱执行，环境隔离
  • 丰富的 API/SDK，适合嵌入现有系统
  • 擅长：架构设计、代码重构、Bug 定位

最适合：以写代码为主的开发任务

Claude Code

「双手」— 执行与编排引擎

  • 终端原生，直接操作本地文件
  • Shell + Python + Git 全流程
  • CLAUDE.md 项目级持久记忆
  • 擅长：多步骤编排、文件操作、自动化流水线

最适合：端到端自动化工作流

本项目为什么选 CC

需要大量文件读写（JSON/HTML/PDF）
需要跑 Python 脚本、Chrome 渲染
需要多步骤编排（搜→验→写→校→出）
CLAUDE.md 提供项目记忆 + 触发词
拖文件夹进去说三个字就完事

你怎么选

写代码为主 → Codex
操作文件、跑脚本、编排流程 → CC
也可以两者结合：Codex 当脑 + CC 当手
没有万能工具，只有适合你工作流的工具

迭代方法论：发现错误 → 改规则 → 永久修复

传统开发修 Bug 改代码。Agent 时代修 Bug 是改提示词——改一次，永不再犯

1

"洛阳不是万亿城市"

加 29 城白名单，搜索阶段即过滤

2

"日报周报有重复"

三层去重：精确匹配→相似度→指纹

3

"搜'管理办法'命中率低"

改用业务实义词，命中率 30%→80%

4

"URL 可能是编的"

双重 WebFetch 验证（Step 2.5+4.5）

5

"老问 Yes/No 太烦"

CLAUDE.md 固化零打扰规则

不是修一条数据，是修一个规则

发现洛阳 → 不是删掉它，是加白名单 → 所有非万亿城市永久过滤。

提示词 + 校验脚本 = 双保险

提示词告诉 Agent 怎么做，脚本验证它做对没有。两层配合。

28 次提交，0 次改数据

全是改提示词、CLAUDE.md、校验规则。100 份报告也不会有同类错误。

Agent 的迭代不是修 Bug，是进化规则
